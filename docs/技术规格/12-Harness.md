## §0 这份文档解决什么问题（写给外行）

这份文档做一件事：**确保 Agent 不是「看起来干完了」，而是「真的干对、干对到底」**。两个机制：

| 机制 | 一句话 | 类比 |
|---|---|---|
| 测试驱动自闭环修复链路 | Agent 改完代码必须自己跑测试证明改对了 | 写完作业自己对答案，且不能把对的题改错 |
| 检查点与反思 | 长任务中途不停对表，跑偏就拉回，出事能兜底 | 开车用实时导航，每过一个路段确认还在去目的地 |

**过程（外行版）**：

- **自闭环修复**：Agent 改完代码 → 在隔离环境跑测试（跑挂不弄脏你手上的东西）→ 失败信息结构化喂回（哪个测试挂/断言期望 vs 实际/错误堆栈/改动差异）→ 按信息定向修（禁止绕过测试、禁止删测试假装通过）→ **双重校验**：「原来错的变对了（Fail2Pass）+ 原来对的没被碰坏（Pass2Pass）」两者齐了才算完成。
- **检查点**：Agent 自己把任务拆成步骤，每完成一步就更新进度（报站）；系统在**步骤边界**对照完成判据核验产出、自检目标是否漂移。同时系统盯着行为兜底——嘴上说完成实际没干、长期不更新进度、或踩到危险信号（多文件改动/删除/权限被拦/上下文快满）都会**强制介入**；高风险步骤由独立 Agent 复核；连续失败 3 次强制停机。

## 1. 目标与范围

**本模块回答：怎么从「让 Agent 完成任务」到「确保 Agent 正确地完成任务」？**

Harness 六层（上下文管理 / 工具系统 / 任务编排 / 记忆状态 / 评估观测 / 约束校验与失败恢复）中，前五层已由 `01`-`11` 落地或定义。**本模块补齐第三、第六层缺口 + 整合成闭环**：

- **测试驱动自闭环修复链路**（长任务四方案·方案三）：补丁生成 → 隔离沙箱单测 → 失败归因 → 定向重试 → Fail2Pass/Pass2Pass 双校验——从「偶然正确」到「必然正确」。
- **TODO 系统 + 双层检查点**（方案二）：todo 是模型语义层的任务声明（报站），步骤边界触发检查点；行为观察兜底（防失效）——防目标漂移、防失控。
- **约束校验与失败恢复**（第六层）：断路器、失败重试策略切换、错误模式沉淀、代码回滚、规则量化追踪——错了能兜底。
- **系统提示词分层**：机制如何让模型知道——常驻核心 / 延迟加载 / 触发式注入。

**D5 优先级落定**：方案四（监控评测）+ 方案三（测试闭环）捆绑优先——**方案四已由 `07`+`11` 落地**，本模块聚焦方案三为主干、方案二为中优先，方案一（三层分层记忆）在 `08` 已确认的扁平文件路线内以「错误模式沉淀」形态体现（T34）。

**不在本模块范围**：
- 监控埋点/评测体系 → `07`/`11`（本模块是它们度量的**被改进对象**）
- 权限/Hook 本体 → `06`（本模块复用其机械化约束能力）
- 记忆基建 → `08`（错误模式沉淀是消费方，不重建记忆系统）
- TodoWrite 工具本体 → `03`（本模块定义其语义层规则、进上下文机制与检查点联动；工具实现与注册在 03）
- 压缩机制本体 → `01`（本模块只定义 todo 快照的保真要求，压缩豁免已回写 01）
- OS 级沙箱 → `06` D14（Windows 应用层防御；本模块的「沙箱」= worktree 隔离 + 命令级限制，见 §3.1）

- **消费 `04`/`05`**：todo 列表持久化到会话状态、TUI 实时面板渲染（非从 LLM 文本抠）。

- **消费 `06`**：Hook 机械化约束（pre_tool_use 拦截）是「约束校验」的既有执行器；本模块补「失败后策略」而非重复拦截逻辑。

## 3. 详细设计

### 3.1 测试驱动自闭环修复链路（方案三，主干）

**核心**：把「测试结果 → 归因 → 驱动重试」的反馈回路建起来。当前 Loop 工具结果注入后下一轮 LLM 决策完全自由，没有被测试结果「牵引」到修复路径上——本模块补上这条反馈闭环。

```
patch 生成
   │
   ▼
TestRunner 在隔离沙箱跑测试 ──────► TestingEvent(test_passed / test_failed / regression_detected)
   │                                   │
   │  test_failed                      │ test_passed
   ▼                                   ▼
调用栈/失败信息归因 ──► 定向重试    Pass2Pass 验证（原通过的没被碰坏）
   │（LLM 被失败信息                  │
   │  牵引回修复路径）                 ▼
   ▼                            Fail2Pass 确认（原失败的被修复）──► 完成
  回到 patch 修复（不自由发挥）
```

**TestRunner 工具**（新内置，03 注册）：

```python
# tools/test_runner.py
class TestRunner(Tool):
    """封装 Bash + 隔离沙箱 + 结果解析；输出结构化 TestingEvent 而非裸文本。"""
    name = "TestRunner"
    # 参数：command（测试命令）、sandbox（worktree 名 | temp 目录 | 当前目录）
    # 输出：TestingEvent —— passed / failed / regression_detected
    #       failed 时带：失败测试名、断言信息、调用栈、diff 摘要 → LLM 归因
```

- **隔离**：默认在 `10` 的 worktree 沙箱跑（复用变更保护——跑挂不污染主工作区）；轻量自测可用临时目录。
- **与 `11` 判分环境的边界**：`12` 是任务内**快速自测**（worktree + 本地命令，秒级）；`11` 是任务外**官方判分**（SWE-bench Docker harness，分钟级）。前者驱动修复迭代，后者裁定最终结果，共用 Fail2Pass/Pass2Pass 判定口径。
- **归因**：TestRunner 返回结构化失败（哪个测试/断言/栈/diff），LLM 据此定位而非瞎试；提示词约束「测试失败必须基于失败信息修复后重跑，不得绕开测试」。
- **TestingEvent**：并入 `02` 事件流（05 可渲染「正在跑测试…」）。

**激活条件**（何时进入自测/修复回路，T32）：

| 触发 | 条件 |
|---|---|
| 写码后建议 | Edit/Write 落在代码文件（非文档白名单）→ 提示词引导「改完自测」 |
| 项目有测试基建 | 启动时 Glob 探测 `*_test.*` / `pytest.ini` / `jest.config` / `package.json scripts.test` → 注入「此项目有测试，改代码后应自测」 |
| 任何失败 | 工具报错或测试失败 → 进入归因→定向重试回路，提示词约束「不得绕开测试/伪造通过」 |
| 用户显式 | 任务描述含「验证/确认不破坏/跑测试」 |

### 3.2 TODO 系统（模型语义层 · 报站）

**定位**：TodoWrite 是模型对任务的**语义声明**——拆步骤、报进度，是**主检查点的触发源**（§3.3 第一层）。它不充当安全兜底（安全兜底由行为观察承担，§3.3 第二层）。

**结构化升级**（T36=B，判据可选）：

```
todo（列表，≤5-8 项）→ task → steps（每步：description + 可选 accept_criteria）
```

- **task 初始化**：agent 设置 plan = 若干 steps（这就是「步骤化 plan」）。
- **accept_criteria 可选**：**完成型步骤必写**（改某函数/修某 bug → 「测试 X 通过」），**探索型步骤可省**（调研/理解 → 无机械判据，轻量检查兜底）。引导写成**可机械验证**形式（测试通过 / grep 出某模式 / 文件存在 / 命令 exit 0）——硬判据能自动跑，软判据靠自评。

**todo 进上下文机制**（怎么让模型知道当前任务状态）：

```
主通道（模型主动）：
  TodoWrite 调用 → 03 解析 → 04 会话状态更新
       ├─► tool_result 回传【最新完整 todo 列表】进上下文  ← 语义时刻，一步一次，低频
       └─► TUI 事件 → 05 面板渲染（给人看）

系统侧强制刷新（模型没主动时，4 时点）：
  ① 检查点触发  → 当前 todo 快照 + 自检提示合并成一条 system-reminder
  ② 上下文压缩后 → 快照独立重灌（01 已补压缩豁免）
  ③ 行为观察发现滞后 → 快照 + 「todo 已落后于行为，请更新」
  ④ 会话恢复 → 快照作为恢复上下文的一部分
```

**硬约束**：
- **todo 不进 system prompt 常驻区**——system prompt 是前缀缓存固定前缀，todo 一变缓存全失效。只能以**对话内容**形式进上下文，进得越少越准。
- **快照压缩豁免**：L2 不摘、L3 压缩后重灌（已回写 `01` §5.3/§5.4）。
- **快照必须保真**：回传完整列表，不是 diff（diff 让模型拼不回来）；快照 ≈ 200-500 token，成本可忽略。

**模型侧规则**（常驻系统提示词，§3.4）：
- 非平凡任务开始前必须先建 todo（task + steps）
- 进度变化即更新（报站），不攒到结尾
- 列表收敛 ≤ 5-8 项——超出即子任务粒度太大，需拆成多轮推进
- Replan 时整体重写（旧列表废弃，不修补）

### 3.3 检查点与反思（方案二，双层）

**问题**：扁平事件流没有「阶段」概念，长任务微小的路径偏移会累积成灾难。

**双层结构**（T33）：

```
第一层：声明驱动（主检查点，agent 主动报站）
  task_update 更新到步骤边界
    → 注入「该步骤产出 vs 完成判据」验证 + 目标一致性自检
    → 高风险步骤边界触发 10 Verification 子 Agent 独立复核

第二层：行为观察（兜底，Harness 被动监控，不依赖 agent 自觉）
  ① 声明 vs 行为不一致：说完成了但行为未干完 → 拦截警告
  ② 遗忘更新：todo 状态长期滞后于实际行为 → 强制刷新快照 + 提示补更新
  ③ 安全类信号：断路器 / 权限拒绝 / 跨文件大改 → 始终生效

激活门控：第一层随 todo 激活（长任务专属）；第二层③始终生效（安全兜底不能关）
```

**为什么两层**（评估结论）：
- **声明驱动给精度**：只有 agent 知道「这一步目标达成」的语义时刻，工具调用序只能推导出粗粒度阶段，推不出「步骤 3/5 干完了」；且步骤边界能验证「产出 vs 完成判据」，比空泛的「自问目标对齐」具体。
- **行为观察兜底**：工具调用是干活**必然产生**的行为，随时可观察；`task_update` 是**可省略**的声明。若把检查权全交给被检查者，agent 忘更新时检查点整体消失——兜底把检查权留在系统手里。

**检查点与 todo 快照绑定**：每次检查点触发 = 「刷新当前 todo 快照 + 注入自检提示」一次完成。否则模型脑里的 todo 是 20 轮前的旧快照，自检对表失真。

**Replan 机制**：检查点发现路径不可行 → 重新规划而非硬着头皮（02 已有 Plan Mode，12 在检查点接入切换；Replan 时整体重写 todo）。

### 3.4 系统提示词分层（机制如何让模型知道）

一条规则是否进常驻系统提示词，看它**是否每轮都高价值**——常驻内容每轮都读（01 前缀缓存），越贵越精挑：

| 层 | 内容 | 成本/时机 |
|---|---|---|
| 常驻核心 | TODO 维护规则（先建/随更/收敛≤5-8/Replan 重写）；「完成型步骤必写判据、探索型可省」；铁律「先读后编辑」「测试失败必须修复后重跑、不得绕开测试/伪造通过」 | 便宜，每轮都读（01 预算内） |
| 延迟加载 | TestRunner 完整语义（参数/隔离/TestingEvent 格式）、激活条件细节 | 贵，激活才读（09 ToolSearch） |
| 触发式注入 | 检查点：todo 快照 + 自检提示（§3.3 绑定）；测试闭环：Fail2Pass/Pass2Pass 判定口径（与 `11` 同一把尺子）；当前阶段 + 下一步建议 | 激活时注入（02 system-reminder） |

**要点**：机制分三层让模型知道——常驻铁律防跑偏（便宜、每轮在），延迟语义省 token（激活才读），判定口径在用到那一刻才给。与 08 注入式、01 前缀缓存、09 ToolSearch 一致。

### 3.5 约束校验与失败恢复（第六层）

| 机制 | 载体 | 说明 |
|---|---|---|
| 机械化约束 | `06` Hook（pre_tool_use 拦截） | 系统级强制，不靠 Agent 自觉 |
| 断路器 | `02`（连续失败 N 次挂起 + MAX_ITERATIONS） | 不允许无限重试烧 token |
| 失败重试 + 策略切换 | `12` | 工具失败不简单重试：npm install 失败 → 查版本 → 尝试 flags → lockfile 冲突 → 诊断报告 |
| 错误模式沉淀 | `08` feedback 记忆 | 失败根因写经验库（如「Edit 前必须 Grep 确认 old_string 唯一」「空判据步骤容易烂尾」），下次自动遵守 |
| 代码回滚 | `10` worktree 变更保护 + git 追踪 | 引入 bug 精确回退，不靠 Agent 手动恢复 |
| 规则量化追踪 | `07` span 数据 + `12` 接口 | 遵守率可量化可追溯（见 §3.6） |

### 3.6 规则量化追踪

用 scoring function 量化 Agent 对规则的遵守程度——「先读后编辑」「测试失败必重跑」「完成型步骤必写判据」「禁止碰测试文件」等。这是 Harness「约束有效性」自身的度量。

```python
# harness/rules.py
def rule_adherence(rule_id: str, run_id: str) -> RuleStats:
    """从 07 trace 聚合某条规则在一个 run 中的遵守率。
    - 「先读后编辑」：edit 前同轮有 read（trace 工具调用序）
    - 「测试失败必重跑」：test_failed 事件后是否跟了修复+重跑
    - 「完成型步骤必写判据」：task 初始化时 steps 是否带 accept_criteria
    - 「禁止碰测试文件」：tool.exec 里 write 目标是否命中 *_test.* 白名单外
    """
```

- 数据源全在 07 span（tool.exec 序列、permission.check、hook.run），`12` 只定义判定规则，不新增埋点。
- 效果由 `11` 复测度量：一次一变量改了某条规则 → 遵守率是否变化 → 任务结果是否变化。

### 3.7 上下文管理兜底（六层第 1 层，引用为主）

- 渐进式披露、CLAUDE.md 入职、system-reminder 动态注入 → `01` 已落地。
- **上下文线程化** → `10` SubAgent（不同任务独立上下文，互不污染）。
- **上下文重启**：长任务接近爆满 → `01` 三层压缩是轻量形态；需要真正换手时，`10` Fork 式继承 + 摘要移交（`01` 压缩摘要 + `10` Fork 前缀缓存复用天然衔接）。压缩后 todo 快照重灌（§3.2）。

## 5. 验收标准

- [ ] `TestRunner` 在 worktree 沙箱跑测试，输出结构化 `TestingEvent`（passed/failed/regression_detected + 归因信息）
- [ ] 测试失败 → 归因 → 定向重试闭环跑通：LLM 基于失败信息修复后重跑，非自由发挥
- [ ] Pass2Pass/Fail2Pass 双校验生效：修对但碰坏原测试 → regression_detected，不标完成
- [ ] 测试在隔离环境跑挂不污染主工作区（worktree 变更保护）
- [ ] 测试闭环按 4 激活条件进入：写码后建议 / 探测到测试基建注入 / 失败即进修复回路 / 用户显式要求
- [ ] todo 结构生效：task 含 steps；完成型步骤带判据、探索型步骤可省略（不拦截）
- [ ] TodoWrite 调用后 tool_result 回传完整快照进上下文，同时更新会话状态并渲染 TUI 面板（非从 LLM 文本解析）
- [ ] 检查点：task_update 到步骤边界 → 注入「产出 vs 判据」验证 + 目标一致性自检（刷新快照 + 提示一次注入）
- [ ] 第二层兜底：声明 vs 行为不一致 → 拦截；todo 长期滞后 → 强制刷新 + 提示更新
- [ ] 安全类信号（断路器/权限拒绝/跨文件）不依赖 todo 激活，始终生效
- [ ] 高风险步骤边界触发 Verification 子 Agent 独立审视，产出与主 Agent 不同的检查结论
- [ ] todo 快照压缩豁免生效：L2 不摘快照；L3 压缩后快照重灌，模型检查点对表用最新状态
- [ ] todo 快照不进 system prompt 常驻区（前缀缓存不受 todo 更新影响）
- [ ] 断路器：连续失败达到上限挂起，不无限重试烧 token
- [ ] 错误模式沉淀：一次 Edit 失败根因写入 08 feedback 记忆，下次相关场景可被提取
- [ ] 代码回滚：worktree 变更保护下，失败改动可精确回退
- [ ] 系统提示词三层分工生效：常驻铁律每轮在、TestRunner 语义延迟加载、判定口径激活时注入
- [ ] `rule_adherence` 从 07 trace 算出「先读后编辑」「测试失败必重跑」「完成型步骤必写判据」遵守率；规则改动经 11 复测验证效果
- [ ] 12 的改进跑通 `11` 一次一变量复测闭环（具体现象消失判定为改对）
