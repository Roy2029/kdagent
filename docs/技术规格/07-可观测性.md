# Coding Agent 技术规格 · 07 可观测性

> 状态：**已确认 v0.3**（2026-08-12）｜里程碑：阶段 3（能用+可控档）｜依赖：`02`（LLM 调用/Agent.run 埋点）、`03`（工具结果元数据）、`06`（权限/Hook 决策）、`01`（压缩事件上报）｜被依赖：`08` 记忆（消费 trace 数据源）、`11` 评估（复用 span 关联 eval 跑分）

---

## 1. 目标与范围

**本模块回答：Agent 工作时发生了什么？出了问题怎么查？**

- **数据模型**：Session / Trace / Span 三层（D2），以会话为追踪单元——一次「修复 Bug」可能是数十次 LLM 调用 + 工具执行的组合，单请求模型装不下。
- **三大数据**：Tracing（链路）/ Logging（详情）/ Metrics（聚合），本地轻量起步。
- **三层能力**（用户深化资料）：交互端实时可观测 / 后台可监控 / 离线可分析——**本地档只落第一、第三层的最简形态**，后台监控层由 OTel 后端（生产级）承接。
- **为 `01` 提供标定基建**：T7（压缩阈值校准）、T8（L2 经济参数标定）所需的测量数据。
- **为评测迭代提供数据支撑**：trace 携带版本指纹与任务结果，支撑按版本聚合对比、fail2pass/pass2pass 定位（§3.8；评测**编排**属 `11`，本模块只负责数据层）。

**不在本模块范围**：
- OTel Collector / Jaeger / Tempo / Prometheus / Grafana 等**重后端部署**——预留导出接口，生产级接入（D2「预留 OTel 导出接口」）。
- 告警系统、统一仪表盘、数据湖 ETL、用户行为分析——属于后台监控/离线分析层，生产级。
- 会话内容（消息/工具结果原文）的持久化 → `04`；本模块只记**遥测视图**（span/metrics/日志），两套数据用同一 `session_id` 关联。

## 2. 与相邻模块关系

```
   02 ReAct Loop ──► 03 工具执行 ──► 06 权限/Hook
        │  llm.call span   │ tool.exec span   │ permission/hook span
        ▼                  ▼                  ▼
   ┌─────────────── 统一 sink（Telemetry）───────────────┐
   │  Trace（span 树） + Logging（脱敏详情） + Metrics（聚合） │
   └───────┬───────────────────────────────┬────────────┘
           │ 压缩事件（01）                 │ 提供 trace_context（contextvars）
           ▼                               ▼
     {kdagent_dir}/obs/                02/03/06 埋点
     （traces/metrics 本地 JSONL）
           │
           ├─► 05 挂载点：状态栏 token / /metrics 面板（T9）
           ├─► 01 标定：压缩前后 token、L2 成本数据 → T7/T8 校准
           └─► OTel 导出接口（预留，生产级接后端）
```

- **消费 `02`**：`Agent.run()` 每次调用 = 一个 Trace；LLM 调用 = 子 Span；`text_delta`/usage/error 是 span 的 attributes/logs。
- **消费 `03`**：`ToolResult.duration_ms`、`is_error` → tool.exec span 的耗时与状态。
- **消费 `06`**：权限裁决（allow/deny/ask + 命中的规则）与 Hook 执行（id/reject/耗时）→ span。
- **消费 `01`**：压缩事件上报（触发类型/前后 token/耗时）→ context.compact span，是 T7/T8 标定的数据源。
- **复用 `04`**：`session_id` 共用（07 存遥测、04 存内容，同 id 关联）；过期清理联动（obs 数据随会话 30 天清理）。
- **为 `05` 提供**：状态栏 token 是监控指标的最初形态，`/metrics` 是 T9 待决的可视化入口。
- **为 `08`/`11` 提供**：trace 是记忆提取（会话回放）与评估（span 关联 eval 跑分）的原始数据。

## 3. 详细设计

### 3.1 数据模型

```
Session（会话）          一次完整端到端交互        ← 04 的 sid
 └─ Trace（追踪）         一次用户输入 + 响应链路   ← 02 一次 Agent.run()
     └─ Span（跨度）     一个具体操作（最小单元）
         ├─ 因果：parent_span_id 串成树
         └─ 详情：span.logs（半结构化，含脱敏）
```

```python
# obs/model.py
@dataclass
class SpanLog:
    level: Literal["debug", "info", "warn", "error"]
    message: str
    ts: int

@dataclass
class Span:
    span_id: str
    trace_id: str
    parent_span_id: str | None
    name: str                        # llm.call / tool.exec / permission.check / ...
    kind: str                        # client / tool / permission / hook / context / session
    status: Literal["ok", "error"] = "ok"
    start_ts: int = 0                # ms
    end_ts: int = 0
    duration_ms: int = 0
    attributes: dict = field(default_factory=dict)   # 结构化：model/tokens/decision/...
    logs: list[SpanLog] = field(default_factory=list)

@dataclass
class Trace:
    trace_id: str
    session_id: str
    user_input_snapshot: str         # 脱敏后的输入摘要
    root_span_id: str
    spans: list[Span] = field(default_factory=list)   # 以 parent_span_id 恢复树
    ts: int = 0
    attributes: dict = field(default_factory=dict)   # 版本指纹 / eval 关联（见 §3.8）
```

**span 类型表**（埋点清单，跨模块）：

| name | kind | 出处 | attributes 要点 |
|---|---|---|---|
| `session.start` / `session.end` | session | 04 | session_id |
| `trace.run` | — | 02 | 输入摘要、停止原因 |
| `react.iteration` | client | 02 | 轮次序号、tool_use 数 |
| `llm.call` | client | 02 | model、in/out/cache tokens、stream 耗时 |
| `tool.exec` | tool | 03 | tool 名、duration、is_error |
| `permission.check` | permission | 06 | decision、命中 rule |
| `hook.run` | hook | 06 | hook id、event、reject |
| `context.compact` | context | 01 | 触发类型、前/后 token、耗时 |
| `session.restore` / `cleanup` | session | 04 | 恢复路径、清理数 |

### 3.2 统一 sink：Telemetry

埋点不散落各模块——收敛到一个 `Telemetry`，用 **contextvars** 传递当前 trace/span（Python 3.11，避免显式参数穿层，侵入最小）。

```python
# obs/telemetry.py
_current_span: ContextVar[str | None] = ContextVar("_current_span", default=None)

class Telemetry:
    def __init__(self, obs_dir: Path, exporter: SpanExporter): ...

    @contextmanager
    def span(self, name: str, kind: str, attributes: dict = None):
        parent = _current_span.get()
        s = Span(span_id=gen_id(), trace_id=current_trace(), parent_span_id=parent, ...)
        _current_span.set(s.span_id)
        try:
            yield s
        except Exception as e:
            s.status = "error"; self.add_log(s, "error", str(e)); raise
        finally:
            s.end_ts = now(); s.duration_ms = s.end_ts - s.start_ts
            self._exporter.export([s])           # 实时落盘，不攒批
            _current_span.reset()

    def add_log(self, span_id, level, message, attributes=None): ...
    def metric(self, name: str, value: float, labels: dict = None): ...  # 内存聚合
    def flush(self) -> None: ...                 # session 结束时落盘 metrics
```

- **自动父子**：嵌套 `span()` 自动串 parent，埋点方不关心链路。
- **trace 上下文**：02 `Agent.run()` 进入时 `begin_trace()`，退出时 `end_trace()` 记停止原因。
- **实时落盘**：span 一结束就写一行（崩溃不丢已产生数据，与 04 JSONL 同思路）。

### 3.3 Tracing：本地存储

```
{kdagent_dir}/obs/
   traces/{sid}/{trace_id}.jsonl     # 每行一个 span（含其 logs），trace 头行含输入摘要
   metrics/{yyyymm}.jsonl            # 每行一个聚合桶（trace 结束时 / session 结束时写）
```

- 单个 trace 一个文件，span 树用 `parent_span_id` 重建。
- **保留策略**：随 `04` 会话过期清理联动删除（同 30 天可配置/可开关，D12）。

### 3.4 Logging：脱敏

- **Prompt 默认只落摘要**（长度 + 首尾片段），完整 prompt 由 `debug.log_full_prompt: true` 显式开启——本地日志常含业务代码，防误导出泄露。
- **工具参数**：本地完整记录（调试必需）；`SpanExporter` 出口处提供脱敏钩子（正则规则可配置，如 `api_key` 值打码），默认空规则。
- **错误**：异常堆栈记入 span.logs（error 级），与 `02` ErrorEvent 联动。

### 3.5 Metrics：聚合口径

内存聚合 + 落盘，全部按 `session_id` / provider 两个维度切分：

| 指标 | 口径 |
|---|---|
| token 消耗 | in / out / cache 分列（D9：DeepSeek 缓存命中折扣大，cache 单独统计） |
| LLM 调用 | 次数、avg/p99 延迟、错误率 |
| 工具调用 | 各工具次数、成功率、平均耗时 |
| 权限决策 | allow / deny / ask 分布、HITL 次数、命中规则 Top-N |
| Hook | 执行次数、reject 次数、失败数 |
| 压缩 | 次数、触发类型（auto/force/manual）、压缩比 |
| **成本估算** | token × `01` L2 计价表（T5-1 关联：按 provider 配置化，07 提供实测数据校准） |

### 3.6 对 `01` 的标定支持（T7/T8 落地）

`01` 在压缩事件上报完整上下文，`07` 聚合出校准报表：

- **T7（压缩阈值校准）**：每次 `context.compact` 记录「触发时 token 数 / 压缩后 token 数 / 压缩比 / 触发类型」。聚合 N 个真实会话 → 看阈值（50K/200K/167K）是否贴合真实使用曲线，压缩后是否回到合理水位。
- **T8（L2 经济参数标定）**：每次 L2 压缩记录「压缩前 in/out token、缓存命中率、压缩后 token 变化、耗时」，按 provider 聚合 → 标定 `C_in/C_out/C_hit` 与 `ONLINE_COMPRESS_MIN`（T5-1）。
- **交付形态**：`/metrics compact` 输出校准表格（T9 落地后并入面板）。

### 3.7 可视化：监控形态（T9 已决：方案 A）

`05` 状态栏 token 是**最初形态**。**监控**的本地形态 = **方案 A**：Textual 内嵌 `/metrics` 面板（推屏 MetricsScreen：当前 session 聚合 token/耗时/工具统计/权限统计 + 历史摘要），全在 TUI 内、零外部依赖，符合「本地轻量起步」。

> 监控（当前会话健康度）与**评测对比**（跨版本对比指标/任务 diff）是两回事：前者由 `05`+`07` 的 `/metrics` 承担；后者由 `11` 评估承担，`07` 在数据层支撑（§3.8）。后台监控层（Grafana 等）留生产级 OTel 后端。

### 3.8 为评测迭代提供数据支撑（用户驱动场景）

**驱动场景**：构造评测任务集 → 每次改 prompt / 超参数 / harness 方案 → 跑一遍评测 → 对比总体性能与成本指标、fail2pass/pass2pass 等任务级数据 → 发现问题 → 定位、观察 trace、排查、复现。

`07` 不承担评测**编排**（任务集管理/跑批/打分属 `11`），但数据层必须让上述闭环跑得动：

**1. 版本指纹**：每次评测跑批带 `run_id = config_hash`（prompt + 超参数 + harness 配置的哈希）。该 run 下的每个 trace 打上 `attributes["eval.run_id"]`，按版本聚合/对比成为可能。

**2. 任务关联 + 结果回填**：trace 关联 `attributes["eval.task_id"]`；打分完成后把 pass/fail/score 回填 `eval.passed` / `eval.score`。trace 因此同时承载「发生了什么」与「结果如何」——失败任务的排查从 trace 直接进入。

**3. 对比聚合接口**（数据层提供，`11` 消费）：

```python
# obs/query.py（读 traces/*.jsonl，纯函数，不建索引——本地数据量级足够）
def metrics_by_run(run_id: str) -> RunMetrics: ...   # pass rate / 成本 / 延迟 / token
def diff_runs(run_a: str, run_b: str) -> TaskDiff: ...# 任务级 diff：
                                                     # fail2pass(修复) / pass2fail(回归)
                                                     # / fail2fail / pass2pass
def trace_by_task(run_id: str, task_id: str) -> Trace: ...   # 失败定位入口
```

**4. 排查路径**：`diff_runs` 命中 pass2fail（回归）→ `trace_by_task` 取该 run 的 trace → span 树观察（LLM 决策、工具调用、权限/Hook、压缩点）→ 回填上下文完成复现。

**实现要点**：版本指纹/任务关联走 `Trace.attributes`（§3.1），不新增结构；`01` 压缩标定（§3.6）与评测对比共用同一套 trace 数据。

### 3.9 OTel 导出预留（D2）

```python
# obs/exporters.py
class SpanExporter(Protocol):
    def export(self, spans: list[Span]) -> None: ...
    def shutdown(self) -> None: ...

class JsonlExporter:                  # 本地实现（默认）
    def __init__(self, obs_dir: Path): ...
    def export(self, spans): ...       # 按 (sid, trace_id) 落盘 JSONL

class OTLPExporter:                   # 预留：生产级接入，本阶段不实现
    """OTLP/gRPC 上报 → OTel Collector → Jaeger/Tempo/Prometheus/Grafana。"""
```

- 配置 `otel: {enabled: false, endpoint: ""}`；`enabled: true` 时 Telemetry 用 OTLPExporter 替换默认。
- span 模型（id/name/kind/parent/status/attributes）已对齐 OTel 字段语义，导出映射零转换。
- `07` 只保证**本地链路可用**；OTLP 后端接入是生产级工作。

### 3.10 关键参数

| 参数 | 初值 | 含义 |
|---|---|---|
| `debug.log_full_prompt` | `false` | 完整 prompt 落盘开关（默认摘要） |
| obs 保留天数 | 随 `04`（30 天可配置/可开关） | 联动清理 |
| metrics 落盘时机 | trace 结束 + session 结束 | 两次聚合 |
| `otel.enabled` | `false` | OTLP 导出开关 |

## 5. 验收标准

- [ ] 一次 `Agent.run()` 产生一条 trace，span 树父子关联完整、时序正确
- [ ] `llm.call` span 记录 model、in/out/cache tokens、耗时；错误时 status=error 且堆栈入 logs
- [ ] `tool.exec` span 复用 `ToolResult.duration_ms`/`is_error`
- [ ] `permission.check` / `hook.run` 产生 span（decision、rule、hook id）
- [ ] `context.compact` 上报触发类型/前后 token → 可聚合出 T7 校准表格
- [ ] L2 压缩成本数据可聚合（T8 标定：token/缓存命中/压缩后变化，按 provider 切分）
- [ ] trace 以 JSONL 落盘 `{kdagent_dir}/obs/traces/{sid}/{trace_id}.jsonl`，每行一个 span
- [ ] 默认 prompt 只落摘要；`debug.log_full_prompt: true` 才落全文；脱敏钩子在 exporter 出口生效
- [ ] metrics 按 session/provider 聚合；`/metrics` 面板展示当前会话健康度
- [ ] obs 数据随 `04` 会话过期清理联动删除
- [ ] `SpanExporter` 协议可插拔：默认 JsonlExporter；`otel.enabled: true` 可换 OTLP（接口就绪）
- [ ] 评测跑批的 trace 携带 `eval.run_id`/`task_id`，打分后回填 `passed`/`score`
- [ ] `metrics_by_run` / `diff_runs` / `trace_by_task` 可跑通：两次跑批按任务级 diff 出 fail2pass/pass2pass；失败任务能从 trace 定位到具体 LLM 调用/工具调用/压缩点
