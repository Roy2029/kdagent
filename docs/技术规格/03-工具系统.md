# Coding Agent 技术规格 · 03 工具系统

> 状态：**已确认 v0.4**（2026-08-14：TodoWrite 结构升级 + tool_result 回传，与 `12` v0.3 对齐）｜里程碑：阶段 2（能跑档）｜依赖：`02`（核心引擎，工具接口被 Loop 消费）、`01`（结果入口压缩 + 快照豁免）、`04`/`05`（todo 状态持久化与渲染）｜被依赖：`06` 权限与 Hook（消费元信息）、`07` 可观测性（消费结果元数据）、`12`（双轨角色）

---

## 1. 目标与范围

**本模块是 Agent 能力的边界**。它回答：模型怎么"动手"。

- **工具接口**：定义统一 Tool 协议，不止"名字+执行"，还携带只读/破坏性/并发安全/参数校验等元信息——为权限（`06`）、并发（`02`）、校验提供依据。
- **工具描述**：这是工具系统**最重要**的部分——描述质量直接决定模型何时调、调哪个、参数怎么传。
- **ToolRegistry**：注册、查找、枚举 schema，向 `02` 的 payload 组装与并发分批提供数据。
- **内置工具集**：能跑档落地一组最小可行动的内置工具。

**不在本模块范围**：
- Function Calling 四步协议的编排 → `02` ReAct Loop（本模块只提供工具本体）
- 权限裁决与 Hook 拦截 → `06`（本模块只提供元信息与 `require_confirm` 预留）
- MCP 外部工具、Skill 编排 → `09` 工具生态（本模块定义内部 Tool 协议，`09` 用 wrapper 适配）

## 2. 与相邻模块关系

```
        02 ReAct Loop
           │ ① schemas()  → tools 字段（payload）
           │ ② partition_tool_calls 用 is_concurrency_safe
           ▼ ③ _exec_one 调 execute()
   ┌───────────────┐   ToolResult    ┌──────────────────┐
   │  ToolRegistry  │ ──────────────▶ │ 02 ConversationManager │
   │  (注册/查找)   │                 └────────┬─────────┘
   └───────▲───────┘                           │ 01 on_tool_result（L1/L2）
           │                                   ▼
    内置工具（本模块）                    01 上下文工程
    元信息 → 06 权限    结果元数据 → 07 可观测性
```

- **对 `02`**：`ToolRegistry.schemas()` 供 payload 组装；`is_concurrency_safe` 供并发分批；`execute` 供 Loop 调用。
- **对 `01`**：工具执行结果经 `02` 的写路径过 `01.on_tool_result`（L1 落盘 / L2 在线摘要）后进历史。**`ReadFile` 读回落盘文件不做二次落盘**（`01` §5.2 读回闭环）。
- **为 `06` 预留**：`is_read_only` / `is_destructive` / `category` 是权限规则（`ToolName(pattern)`）的判定依据；`validate_input` 是执行前校验。
- **为 `07` 预留**：`ToolResult.duration_ms`、调用次数、失败率是 trace 与监控指标的数据源。

## 3. 详细设计

### 3.1 Function Calling 本质（一句话 + 四步）

> **模型负责决策，你负责执行，结果反馈回模型。** 模型永远不直接操作系统——这是安全边界，也是架构边界。

四步协作：① tools 参数声明（告知有哪些工具）→ ② 模型输出 `tool_use`（*只是请求，不意味着已执行*）→ ③ 本地执行，结果以 **user 身份**的 `tool_result` 回传（`tool_use_id` 一一对应）→ ④ 模型继续（信息够了 → 最终回复；不够 → 再调工具）。

### 3.2 工具接口（Tool 协议）

不能只有名字和执行。生产级接口携带元信息，供权限/并发/校验决策，且 **工具定义只在接口一处维护**（发 API 的 schema 与实际实现不会脱节）。

```python
# tools/base.py
from typing import Protocol

class Tool(Protocol):
    name: str
    description: str                    # 六要素描述，见 §3.3
    input_schema: dict                  # JSON Schema（→ 02 ToolSchema）
    category: str                       # filesystem / shell / planning / …

    def is_read_only(self) -> bool: ...           # 只读：权限系统 allow
    def is_destructive(self) -> bool: ...         # 破坏性：权限系统 ask/deny
    def is_concurrency_safe(self, input: dict) -> bool: ...  # 02 并发分批依据
    def validate_input(self, input: dict) -> list[str]: ...   # 错误列表，空=通过
    async def execute(self, ctx: ToolContext, input: dict) -> ToolResult: ...

@dataclass
class ToolContext:                      # 工具运行环境（依赖注入）
    work_dir: Path                      # 相对路径基准
    config: Config
    # 06/07 预留：permission / hooks / observability sink

@dataclass
class ToolResult:
    tool_use_id: str
    name: str
    content: str                        # 文本形态，进历史（01 在此预处理）
    is_error: bool = False
    duration_ms: int = 0
```

**执行流程**（`02._exec_one` 调用处）：

```
validate_input(input) → 有错误 → 直接构造 is_error=True 的 ToolResult（不进 execute）
                             │ 无错误
                             ▼
           require_confirm=True? → 06 权限确认（能跑档为 05 极简 Y/N，见 §3.6）
                             ▼
                       execute(ctx, input)
                             ▼
                    异常 → ToolResult(is_error=True)  （02 统一兜底）
```

### 3.3 工具描述六要素（开发规范）

> **工具描述是最值得打磨的部分。** 差描述只说"做什么"；好描述还说"何时该用/何时不该用/参数约束/返回格式/怎么配合"。

| 要素 | 说明 | 示例（ReadFile） |
|---|---|---|
| 做什么 | 核心功能 | 读取指定路径的文件内容，返回带行号文本 |
| 何时该用 | 典型场景 | 需查看文件完整内容或特定行时使用 |
| 何时不该用 | 反模式 | 二进制文件不可读，请改用 Bash |
| 参数约束 | 输入限制 | 路径必须是绝对路径；大文件建议先 Grep 定位再带 offset/limit 读 |
| 返回格式 | 输出形态 | 带行号前缀的文本；文件不存在返回错误 |
| 与其他工具配合 | 工作流建议 | 定位代码用 Grep → 读片段用 ReadFile（offset/limit）→ 改动用 EditFile |

**验证规则**：六要素是**开发规范**，交由开发者 code review 时人工审查，**不设自动检查机制**（无 lint / 测试断言）。规范保留作为编写指引；语义质量靠人把关。

### 3.4 ToolRegistry

```python
# tools/registry.py
class ToolRegistry:
    """工具的注册中心与查询门面。"""
    def register(self, tool: Tool) -> None: ...        # 重名注册 → 启动时报错
    def get(self, name: str) -> Tool | None: ...
    def all(self) -> list[Tool]: ...
    def schemas(self) -> list[ToolSchema]: ...          # 供 02 assemble_payload 的 tools 字段
    def is_concurrency_safe(self, name: str, input: dict) -> bool: ...   # 供 02 partition
    def validate(self, name: str, input: dict) -> list[str]: ...         # 执行前校验
```

- 单一事实来源：API 的 `tools` 字段、并发分批、校验全部出自 registry。
- 重名注册启动即报错（防止两个工具抢一个名字，模型传参错乱）。
- **扩展点**：`09` 的 MCP wrapper 把外部工具适配为内部 `Tool` 再注册进来（命名 `mcp_<server>_<tool>`）；`04` 的 ToolSearch 延迟加载也走注册表。

### 3.5 内置工具集（能跑档 · T6 建议清单）

| 工具 | 做什么 | 只读 | 破坏性 | 并发安全 | 类别 | 备注 |
|---|---|---|---|---|---|---|
| `ReadFile` | 读文件，支持 offset/limit | ✅ | — | ✅ | filesystem | 读回 L1 落盘文件时不再二次落盘 |
| `WriteFile` | 创建/覆写文件 | — | ✅ | ❌ | filesystem | |
| `EditFile` | 精确替换（old/new + 行定位） | — | ✅ | ❌ | filesystem | |
| `Glob` | 路径模式匹配项目结构 | ✅ | — | ✅ | filesystem | |
| `Grep` | 内容搜索（rg 后端） | ✅ | — | ✅ | filesystem | |
| `Bash` | 执行命令，返回 stdout/stderr/exit code | 动态 | ✅（保守声明） | ❌（保守声明） | shell | 能跑档保守声明，精细动态判断留 `06` |
| `TodoWrite` | 维护任务清单（行为质量） | — | — | ❌ | planning | 语义层声明；双轨角色见 `12` §3.2/§3.3 |

**能跑档定位**：这 7 个覆盖"读-搜-写-改-执行-规划"的最小闭环。`AskUserQuestion`（HITL 交互）、`Task`/SubAgent（隔离并行）、`TestRunner`（测试闭环）分别依赖 `05`/`10`/`12`（阶段 5），不在能跑档清单。

**阶段 5 新增工具**（走同一 `ToolRegistry` 扩展点注册，`12` 定义语义）：
- `TestRunner`（`12` §3.1）：封装 Bash + 隔离沙箱 + 结果解析，输出结构化 `TestingEvent`（passed/failed/regression_detected）供 `02` 事件流与 `05` 渲染；`is_concurrency_safe=False`（跑测试必须串行），默认 `require_confirm` 关闭但经 `06` 权限链路裁决。
- `Task`/`TaskList`/`TaskGet`/`TaskCreate`/`TaskUpdate`（`10` §3.7）：后台任务管理。
- `ToolSearch`/`LoadSkill`（`09`）：延迟工具发现与 Skill SOP 加载。

### 3.6 TodoWrite（规划工具 · 语义报站）

**定位**：TodoWrite 是模型对任务的**语义声明**——拆步骤、报进度，是 `12` 主检查点（声明驱动）的触发源；安全兜底由 `12` 行为观察层承担（双轨角色见 `12` §3.3）。

**结构化升级**（`12` T36=B，判据可选）：

```
todo（列表，≤5-8 项）→ task → steps（每步：description + 可选 accept_criteria）
```

- **task 初始化**：agent 设置 plan = 若干 steps。
- **accept_criteria 可选**：完成型步骤必写、探索型可省；引导写成**可机械验证**形式（测试通过 / grep 出某模式 / 文件存在 / 命令 exit 0）。校验**不拦截**缺失（可选，T36）。

**数据流**：

```
TodoWrite 调用 → execute() 解析 → 04 会话状态（SessionRecord.todos）
       ├─► tool_result 回传【最新完整 todo 列表】进上下文  ← 主通道，一步一次
       └─► TUI 事件 → 05 渲染实时面板（给人看）
```

- **解析**：归一化 `[{content, status, activeForm}]`（含 steps/判据）为会话状态；`05` 从状态读渲染，**不从 LLM 文本里抠**。
- **tool_result 回传完整快照**（非 diff）：模型对 todo 的认知 = 对话中最近一次回传快照；不更新则认知过期，由 `12` 系统侧 4 时点强制刷新兜底（检查点 / 压缩后 / 滞后检测 / 会话恢复）。
- **压缩豁免**：快照 L2 不摘、L3 压缩后重灌（`01` §5.3/§5.4）。
- **只写不查**：无需单独「读 todo」工具——渲染是 TUI 的职责，检查点刷新是 `02` system-reminder 的职责。
- **并发安全 = ❌**（`is_concurrency_safe` 返回 False）：顺序语义，必须单写。

**模型侧规则**（常驻系统提示词，`12` §3.4）：
- 非平凡任务开始前必须先建 todo（task + steps）
- 进度变化即更新（报站），不攒到结尾
- 列表收敛 ≤ 5-8 项——超出即子任务粒度太大，需拆成多轮推进
- Replan 时整体重写（旧列表废弃，不修补）

### 3.7 能跑档的最小确认机制（`06` 的前置预留）

能跑档没有完整权限系统（`06` 在阶段 3），但 `WriteFile/EditFile/Bash` 是破坏性操作，不能裸奔。**折中**：

- Tool 接口预留 `require_confirm: bool`（默认 False；写/Bash 工具置 True）。
- 能跑档由 `05` TUI 做**极简 Y/N 确认**（`require_confirm=True` 且非只读时，执行前弹确认）。
- `06` 阶段把这段确认升级为完整权限规则（deny > ask > allow + 权限模式 + HITL），`require_confirm` 字段被权限系统接管，**本模块只需保留元信息、不实现裁决逻辑**。

> 注意：这不是偷懒，是**按阶段演进**——`06` 到来前先有安全底线，`06` 到来后裁决逻辑收敛到权限模块，工具层不膨胀。

### 3.8 关键参数

| 参数 | 初值 | 含义 | 来源 |
|---|---|---|---|
| `require_confirm` 工具集 | WriteFile / EditFile / Bash | 执行前需确认 | 本方案 |
| 并发批上限 | 同 `02` CONCURRENCY_LIMIT | 防无限并发 | `02` |
| 内置工具数 | 7（能跑档）；阶段 5 增 TestRunner/Task×4/ToolSearch/LoadSkill | 能跑档最小闭环 + 生产级扩展 | D10/`12`/`09`/`10` |
| TodoWrite 结构 | todo → task → steps（判据可选） | 语义报站 + 检查点触发源 | `12` v0.3 |
| TodoWrite 收敛 | ≤ 5-8 项 | 超出即拆轮次 | `12` §3.2/T35 |

## 5. 验收标准

- [ ] 7 个内置工具注册进 registry，`schemas()` 生成的 tools 字段可直接用于 API 请求
- [ ] 内置工具描述遵循六要素规范（人工 code review 审查，非自动化）
- [ ] `ReadFile` 读普通文件正常；读 `01` L1 落盘文件不被二次落盘
- [ ] `Grep`/`Glob` 在项目内搜索正常，结果为文本
- [ ] `Bash` 返回 stdout/stderr/exit code；exit code≠0 时 `is_error=True`
- [ ] 非法参数（如相对路径、缺必填字段）→ `validate_input` 直接拒绝，不执行
- [ ] `EditFile` 精确替换成功；old_string 不唯一时明确报错
- [ ] 破坏性工具执行前触发 Y/N 确认（`05` 接入）
- [ ] `TodoWrite` 调用后 `SessionRecord.todos` 实时更新，tool_result 回传完整快照，`05` 面板渲染（非从 LLM 文本解析）
- [ ] step 判据可选：完成型步骤带判据、探索型步骤省略不拦截
- [ ] TodoWrite 并发安全=False，不与其他工具同批执行
- [ ] `TestRunner` 注册进 registry，输出结构化 `TestingEvent`；并发安全=False（串行）；`12` 双校验判定口径一致
- [ ] 工具执行耗时进入 `ToolResult.duration_ms`（`07` 可观测性可消费）
- [ ] 重名注册 → 启动时报错
